# 歡樂抽獎系統 V1.2.7｜紅包雨手機優化版

## 啟動
1. 解壓縮 ZIP。
2. 在資料夾開啟終端機／黑色視窗。
3. 第一次執行：`npm install`
4. 啟動：`npm start`
5. 主控登入：`http://localhost:3000/admin-login.html`

本機測試主控密碼：`8888`
Render 上架時可用環境變數 `ADMIN_PASSWORD` 改成自己的密碼。

## 正式版功能
- 玩法：戳氣球、砸金蛋、紅包雨（A 集滿型／B 單包開獎／C 分數累積型）。
- 氣球：一般、愛心、星星、花朵、雲朵、彩虹；整盤只用一種造型，可開／關飄動。
- 金蛋：彩色 Q 版蛋、Q 版亮晶晶金蛋。
- 主控自填總格數，最高 500 格；手機版大量格數自然換行、上下滑動。
- 主控只輸入真正有獎的獎品名稱與數量。
- `總格數 - 有獎數量 = 系統自動產生的「再接再厲」格數`。
- 有獎數量超過總格數時禁止儲存。
- 未中獎顯示粉紅緞帶「再接再厲」印章，並使用和中獎不同的音效。
- 氣球戳破、金蛋敲裂、中獎、未中獎四種聲音分開。
- 可設定每位玩家限抽一次；重新整理後同瀏覽器仍不能再抽。
- 玩家抽獎結果與主控完整盤面即時同步。
- 中獎格放大顯示獎品名稱與玩家遊戲名。
- 主控可開啟「清剩餘格」模式；主控開出的格子紀錄玩家名保持空白。
- 主控可複製玩家網址、分享文字、抽獎名單、整盤抽獎畫面。
- 玩家頁也有「複製整盤抽獎畫面」按鈕。
- 主控頁、登入頁、玩家頁使用夢幻淡粉／淡紫／淡藍背景。

## 抽獎紀錄格式
玩家正常抽：`第X格 > 獎品 > 玩家名`

主控清剩餘格：`第X格 > 獎品 > `

## 注意
目前房間資料保存在伺服器記憶體中；重新啟動 Node/Render 服務後，舊抽獎房號會失效。

- 複製分享文字會自動帶上開賽日期與時間。


## V1.2.0 紅包雨正式整合版
- 在原本「戳氣球／砸金蛋」旁新增「🧧 紅包雨」，不是另一套獨立抽獎系統。
- 紅包雨 A／B／C 使用分頁式設定，主控頁不會因三套設定全部展開而變得很長。
- **A 集滿型**：限時搶滿指定紅包數 → 紅包雨停止 → 出現「立即抽獎」→ 獎項名稱快速輪播、逐漸減速 → 停在真正結果。
- **B 單包開獎型**：點到紅包直接開獎；預設每人 1 包。若關閉「每位玩家限抽一次」，主控可改為每局 2／3 包。
- **C 分數累積型**：紅包有正分／扣分，分數最低 0；達到目標分數後與 A 一樣顯示「立即抽獎」與獎項名稱輪播。
- C 的扣分比例與幅度由系統依「簡單／普通／困難」自動控制，主控不需另外設定。
- A／B／C 可各自保存遊戲時間、目標與可玩次數，切換模式不會互相覆蓋。
- 紅包雨的掉落動畫完全在玩家手機本機執行，不把每個紅包位置同步到伺服器，降低免費 Render 的即時同步壓力。
- 紅包雨**不建立第二套獎品池**。戳氣球、砸金蛋、紅包雨 A／B／C 都直接呼叫同一個後端抽獎函式、同一份剩餘獎項庫存與同一份即時抽獎紀錄。
- 原本「總格數」在紅包雨模式顯示為「抽獎池總份數」：`抽獎池總份數 - 有獎數量 = 自動產生的再接再厲份數`。
- 紅包雨開獎請求使用 playId + drawKey 防止同一個按鈕／網路重送造成重複扣獎。
- 玩家名稱在紅包雨模式會先登記，同名不可由另一台裝置重複使用。
- 原本 V1.1.6 的選用預定開賽日期＋時間完整保留，紅包雨也會一起受開賽倒數限制。

### 紅包雨抽獎池範例
若「抽獎池總份數」設定 20：
- A獎 2 份
- B獎 3 份
- C獎 5 份

系統會自動補 10 份「再接再厲」。

A／B／C 玩家最後開獎時，都從這同一份尚有剩餘的 20 份結果中隨機抽出一份並扣除庫存。

### 伺服器壓力
紅包雨動畫、紅包位置、點擊飛字與分數顯示都由玩家裝置自行處理。
伺服器只處理：
- 進入／開始一局
- 最終開獎
- 獎項庫存
- 玩家限制
- 抽獎紀錄

因此不會把所有玩家每一顆紅包的位置持續同步到 Render。


## V1.2.5 手機優化
- 玩家分享不再直接顯示整串網址，只保留複製／開啟按鈕。
- 主控「其他設定」改成收合區，縮短抽獎設定頁面。
- 手機紅包掉落區加高。
- 紅包速度整體加快，新增「極速」。
- 紅包下落加入左右來回漂移。
- 手機同時存在的紅包數量設上限，避免 DOM 過多。
- 移除每顆紅包較重的 CSS filter 陰影。
- 點擊音效改成快取，不再每點一次重新產生音效 Buffer。
- 進度條改用 transform，減少版面重算。
- 點紅包後更快移除，改善連續點擊卡頓。


## V1.2.5 點擊提示優化
- A 模式點到紅包時，不再只顯示 +1，改成直接顯示「已搶 X / 目標 包」。
- B 模式點到紅包時，顯示「已開 X / 可開包數」。
- C 模式點到紅包時，顯示「目前 X / 目標 分」。
- 點擊提示改成較清楚的小氣泡，手機上更容易看清楚目前進度。


## V1.2.5 可玩次數與速度調整
- 紅包雨不再受「每位玩家限抽一次」干擾；A/B/C 只依各自的每人可玩次數與每人最多獲獎數控制。
- 每局完成後，若還有可玩次數，顯示「再挑戰一次（剩 X 次）」。
- 玩家達到最多獲獎數後仍可把剩餘挑戰次數玩完，但不會再取得額外真正獎品。
- 「立即抽獎」按鈕改為藍紫色，與黃色獎品輪播區區分。
- 超快／極速速度調慢，保留左右漂移但更容易點擊。


## V1.2.5 再接再厲計次修正
- 「再接再厲」視為正式抽獎結果，與實體獎品一樣會使用 1 次開獎名額。
- 「每人可玩次數」只控制可挑戰幾局。
- 「每人最多開獎次數」控制可取得幾次抽獎結果，包含「再接再厲」。
- 開獎次數用完後，剩餘可玩次數仍可繼續挑戰，但達標後不再出現第二次開獎。


## V1.2.5 開始次數與手機抽獎按鈕修正
- 玩家按「開始挑戰」時不再立刻扣可玩次數。
- 只有 3、2、1 倒數完成、紅包雨真正開始前，才正式計入 1 次。
- 同一局重複按開始／重送請求會回傳同一個 playId，不會重複扣次數。
- 開始按鈕送出後立即鎖定，避免手機連點造成多次請求。
- 若開始過程連線中斷，會提示「本局沒有扣次數」。
- 達標後的「立即抽獎」改為固定在手機可視視窗中央的彈窗，不再被瀏覽器底部工具列擋住。
- 彈窗支援手機 safe-area，小螢幕也能直接看到並按到「立即抽獎」。


## V1.2.6 C 分數模式顏色規則
- C 分數累積型固定顏色意義：
  - 紅色紅包＝一般加分
  - 金色紅包＝高分加分
  - 紫色紅包＝扣分
- 不再讓小加分紅包隨機變成金色，避免玩家誤判。
- 玩家進入 C 模式開始頁即可看到顏色圖例與規則。
- 加／扣分數仍依難度由系統自動分配，最低分維持 0。


## V1.2.7 C 分數模式新增炸彈
- C 分數累積型新增 💣 炸彈。
- 點到炸彈時，目前分數立即歸 0。
- 炸彈使用獨立黑色外觀，不會和紅／金／紫紅包混淆。
- 炸彈出現率依難度自動調整：
  - 簡單：約 2%
  - 普通：約 4%
  - 困難：約 6%
- 玩家開始頁規則更新為：
  - 紅色＝一般加分
  - 金色＝高分加分
  - 紫色＝扣分
  - 炸彈＝分數歸零
- 保留 V1.2.6 以前的全部修正：可玩次數、開獎次數、再接再厲計次、開始成功才扣次數、手機中央開獎彈窗、紅包區加高、卡頓優化、左右漂移等。
